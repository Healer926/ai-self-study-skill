# 概念学习资料生成 Skill（concept-learner-skill）

> 个人学习设计说明：本 Skill 不是一段“只针对 Agent / 上下文 / Skill”的提示词，而是一条**可复用的概念自学流水线**。你给它任意一个概念，它都按同一套框架产出一份 HTML 学习资料。它适合在 WorkBuddy 中以**项目级 Skill** 的形式被反复调用，因此也能随着仓库一起提交、版本化、分享。

## 适用场景
- 快速吃透一个陌生但重要的 AI / 计算机概念（如 Agent、Context Window、RAG、Fine-tuning、Skill、Prompt 等）。
- 需要一份“能读、能复习、能自测”的结构化资料，而不是零散的聊天片段。
- 想把一次性学到的知识固化成可复用、可迭代的网页笔记。
- 想为某个具体概念快速生成统一格式的讲解页（用于作业、分享或团队 onboarding）。

## 输入信息
- **必填**：1 个**概念名称**（中文或英文术语均可），例如 `Agent`、`大模型上下文`、`Skill`。
- **可选**：学习视角 / 使用场景（例如“从 WorkBuddy 使用者角度理解 Skill”）。未提供时按通用技术视角处理。

## 生成步骤
1. **定学习目标**：用 2–3 条可衡量的目标说明“学完应能做到什么”。
2. **提核心问题**：列出 3–5 个最能检验是否真懂的问题，作为阅读导航。
3. **写个人化解释**：用通俗语言给出你自己的理解，**禁止整段照搬 AI 回复**；先用大白话讲清“它是什么、解决什么问题”。
4. **拆核心机制/组成**：说明内部工作原理或构成要素（如 Agent 的感知—决策—行动循环；上下文窗口的 token 上限与注意力机制）。
5. **给应用案例**：写 1 个具体、可落地的场景，最好带“输入 → 处理 → 输出”的过程。
6. **做概念辨析/边界**：区分易混淆的相近概念，并明确使用局限与不适用的情形。
7. **出参考来源**：补充 2–3 条**真实可访问**的权威链接（论文 / 官方文档 / 权威博客）。
8. **编自测问题**：出 2–3 道自测题（含要点提示），用于自我检验。

## 输出结构
产出一份独立 HTML 文件，板块顺序固定为：
1. 标题与一句话定义
2. 学习目标
3. 核心问题
4. 个人化概念解释
5. 核心机制 / 组成结构
6. 具体应用场景（含过程）
7. 概念辨析与使用边界
8. 自测问题（含要点）
9. 参考来源（带可点击链接与一句话说明）

HTML 需排版清晰、响应式、中文友好；文件命名用小写中划线（如 `agent.html`、`llm-context.html`），放入 `learning-materials/` 目录。

## 资料来源要求
- 链接必须**真实存在、可公开访问**，不得编造或猜测网址；不确定时先核实再引用。
- 优先官方文档、原始论文（如 arXiv）、权威技术博客；避免二手搬运。
- 每条来源附一句“为什么看这个”，说明它验证了材料的哪一部分。

## 自检要求
- [ ] 内容是否加入了个人理解，而非整段复制 AI 对话结果？
- [ ] 参考链接是否逐条点击 / 核实过、能打开？
- [ ] 是否同时写了“优点”和“局限 / 边界”，没有只说好处？
- [ ] 是否包含一个具体应用场景与可操作的步骤？
- [ ] 是否产出固定结构的完整 HTML，且板块齐全？

## 调用示例
在 WorkBuddy 中打开本仓库后，输入：
`@concept-learner-skill RAG`
即可按本框架生成 `learning-materials/rag.html`。本仓库已有的 `agent.html`、`llm-context.html`、`skill.html` 即按此 Skill 生成。
