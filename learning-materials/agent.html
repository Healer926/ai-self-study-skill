Agent（智能体）

一句话定义：Agent 是能“自主感知环境 → 做决策 → 调用工具执行 → 观察结果”循环，以完成目标的 AI 系统，通常围绕大模型（LLM）构建。

① 学习目标

  • 能用自己的话解释 Agent 与普通聊天机器人的本质区别。
  • 能说出 Agent 的基本组成（规划 / 模型 / 工具 / 记忆）与一次运行循环。
  • 能举出一个 Agent 落地的例子，并说明它的价值与风险边界。

② 核心问题

  • Agent 为什么需要“工具 / 函数调用”，而不只是靠模型本身？
  • 记忆（上下文）在 Agent 里起什么作用？
  • 什么时候该用 Agent，什么时候普通提示词就够？

③ 个人化概念解释

Agent（智能体）不是“一个更聪明的模型”，而是一套让模型站稳流程、调用外部能力、并记住发生过什么的工作方式。把大模型想象成“顾问”，Agent 则是“带着顾问去干活的员工”：顾问给思路，员工去查资料、发邮件、跑代码，再把结果回报给顾问，继续下一步。

所以 Agent 的关键不在“模型多强”，而在闭环：它能根据结果决定下一步动作，而不是像聊天机器人那样一问一答就结束。

④ 核心机制 / 组成结构

  • 规划（Planning）：把大目标拆成子任务，例如用 To-Do 列表或 ReAct（推理 + 行动）思路。
  • 模型（LLM）：负责理解与决策，是 Agent 的“大脑”。
  • 工具（Tools）：搜索、代码执行、API 调用等，弥补模型“不能实时获取信息、不能直接执行动作”的短板。
  • 记忆（Memory）：短期用上下文窗口，长期用外部存储（如向量数据库）。
  • 循环：感知 → 思考 → 行动 → 观察，直到任务完成。

⑤ 具体应用场景

场景自动化周报 Agent

输入：自然语言“生成本周项目周报”。

处理：Agent 调用日历 / 文档工具收集本周会议与代码提交记录 → 模型归纳重点 → 调用邮件工具发送。

输出：一份已发送给团队的可交付周报。整个过程无需人一步步指挥，体现了“自主多步推进”。

⑥ 概念辨析、使用边界与易混淆知识点

Agent ≠ 普通 Prompt：Prompt 是一次性指令，一问一答即结束；Agent 有“感知-思考-行动-观察”的闭环与工具，能多步自主推进。

Agent ≠ 自动化脚本 / Workflow：脚本与“工作流”的步骤是预先写死的、确定性的；Agent 的下一步由模型在运行中动态决定，更灵活但更不可预测。

Agent ≠ RAG：RAG 是一种“给模型补上下文”的技术（检索相关知识再生成）；它常被 Agent 当作一个工具来调用。RAG 解决“知识不够”，Agent 解决“流程是否自主”。

Agent ≠ 工具 / Plugin：工具（搜索、代码、API）是被调用的“能力”；Agent 是调度这些工具、决定何时调用的“执行者”。

易混淆小结：大模型（大脑）≈ 顾问；工具 ≈ 手脚；Workflow ≈ 写死的 SOP；Agent ≈ 带着顾问和手脚、按 SOP 灵活干活的员工。

边界：当任务目标模糊、缺少可靠工具，或要求 100% 可复现时，Agent 容易跑偏，应降级为确定性的工作流或脚本。

⑦ 自测问题

  1. 什么情况下用 Agent 反而更糟？
    提示：步骤固定、需可复现、容错低的场景，确定性的脚本 / 工作流更稳。
  2. 没有“记忆 / 上下文”，Agent 在长任务中会出什么问题？
    提示：会丢失前面的子目标与中间结果，导致重复或偏离。
  3. 工具调用解决了模型的哪两个根本限制？
    提示：①无法获取实时 / 外部信息；②无法直接执行动作（发消息、跑代码）。
  4. 为什么“反思 / 自我纠错”对 Agent 很重要？
    提示：模型第一步可能出错，Agent 必须能把错误与反馈留在上下文、据以调整下一步，否则会重复同样的错。
参考答案（点击展开）
  1. 答：当步骤完全固定、要求 100% 可复现、容错率低（如金融对账、合规校验）时，Agent 的“模型动态决策”会带来不确定性与不可控成本，确定性脚本 / 工作流更稳更可审计。
  2. 答：Agent 依赖上下文保存子目标与中间结果；若没有记忆，它会忘记前面的计划与工具返回，导致重复调用、偏离目标或无法收敛。
  3. 答：工具调用弥补①模型拿不到实时 / 外部信息（如当前股价、最新文档）；②模型不能直接执行动作（如发邮件、跑代码、调 API）。
  4. 答：Agent 的每一步由模型决定，首步可能出错；只有把“错误 + 反馈”写回上下文、并据此修正后续动作（如 Reflexion 的“语言反思”），Agent 才能从失败中学习、不再重复同错。这正体现了闭环的价值。
