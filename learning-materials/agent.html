Agent（智能体）

一句话定义：Agent 是能“自主感知环境 → 做决策 → 调用工具执行 → 观察结果”循环，以完成目标的 AI 系统，通常围绕大模型（LLM）构建。

① 学习目标

  • 能用自己的话解释 Agent 与普通聊天机器人的本质区别。
  • 能说出 Agent 的基本组成（规划 / 模型 / 工具 / 记忆）与一次运行循环。
  • 能举出一个 Agent 落地的例子，并说明它的价值与风险边界。

② 核心问题

  • Agent 为什么需要“工具 / 函数调用”，而不只是靠模型本身？
  • 记忆（上下文）在 Agent 里起什么作用？
  • 什么时候该用 Agent，什么时候普通提示词就够？

③ 个人化概念解释

Agent（智能体）不是“一个更聪明的模型”，而是一套让模型站稳流程、调用外部能力、并记住发生过什么的工作方式。把大模型想象成“顾问”，Agent 则是“带着顾问去干活的员工”：顾问给思路，员工去查资料、发邮件、跑代码，再把结果回报给顾问，继续下一步。

所以 Agent 的关键不在“模型多强”，而在闭环：它能根据结果决定下一步动作，而不是像聊天机器人那样一问一答就结束。

④ 核心机制 / 组成结构

  • 规划（Planning）：把大目标拆成子任务，例如用 To-Do 列表或 ReAct（推理 + 行动）思路。
  • 模型（LLM）：负责理解与决策，是 Agent 的“大脑”。
  • 工具（Tools）：搜索、代码执行、API 调用等，弥补模型“不能实时获取信息、不能直接执行动作”的短板。
  • 记忆（Memory）：短期用上下文窗口，长期用外部存储（如向量数据库）。
  • 循环：感知 → 思考 → 行动 → 观察，直到任务完成。

⑤ 具体应用场景

场景自动化周报 Agent

输入：自然语言“生成本周项目周报”。

处理：Agent 调用日历 / 文档工具收集本周会议与代码提交记录 → 模型归纳重点 → 调用邮件工具发送。

输出：一份已发送给团队的可交付周报。整个过程无需人一步步指挥，体现了“自主多步推进”。

⑥ 概念辨析与使用边界

Agent ≠ 普通 Prompt：Prompt 是一次性指令；Agent 有循环与工具，能多步自主推进。

Agent ≠ 自动化脚本：脚本步骤写死；Agent 的步骤由模型在运行中决定，更灵活但更不可预测。

边界：当任务目标模糊、缺少可靠工具，或要求 100% 可复现时，Agent 容易跑偏，应降级为确定性的工作流。

⑦ 自测问题

  1. 什么情况下用 Agent 反而更糟？
    提示：步骤固定、需可复现、容错低的场景，确定性的脚本 / 工作流更稳。
  2. 没有“记忆 / 上下文”，Agent 在长任务中会出什么问题？
    提示：会丢失前面的子目标与中间结果，导致重复或偏离。
  3. 工具调用解决了模型的哪两个根本限制？
    提示：①无法获取实时 / 外部信息；②无法直接执行动作（发消息、跑代码）。
