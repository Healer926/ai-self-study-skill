Skill（可复用技能 / 技能包）

一句话定义：Skill 是把“完成某类任务所需的方法、步骤、约定与提示词”固化下来的可复用单元；在 WorkBuddy 等 Agent 平台中，它让 Agent 在遇到相关任务时自动加载对应能力。

① 学习目标

  • 能区分 Skill、Prompt、Agent 三者的关系。
  • 能说出项目级 Skill 的存放位置与调用方式。
  • 能说明一个好的 Skill 应具备哪些要素。

② 核心问题

  • Skill 相比“把提示词写在聊天里”好在哪？
  • 项目级 Skill 放在哪、为什么只对当前仓库生效？
  • Skill 的 SKILL.md 里哪些字段最关键？

③ 个人化概念解释

Skill 像一本“岗位工作手册”。普通提示词是你每次临时跟助手交代“这次这么干”；Skill 是你把“这类事都该怎么干”写进手册，以后只要遇到这类任务，助手自动翻手册照做。它把一次性的对话经验变成可复用的项目能力，而且可以随仓库提交、做版本管理、团队共享。

④ 核心机制 / 组成结构

  • 触发：用户显式调用（如 @concept-learner-skill），或 Agent 按任务匹配自动加载。
  • 内容：SKILL.md（含 YAML 元数据 name / description + 适用场景 / 输入 / 步骤 / 输出 / 自检）。
  • 范围：项目级 Skill 存于仓库 .workbuddy/skills/<name>/，只对该仓库生效；用户级存于 ~/.workbuddy/skills/，全局可用。
  • 沉淀：把零散经验结构化、可核查、可迭代。

⑤ 具体应用场景

场景概念自学 Skill（本仓库即实例）

输入：在 WorkBuddy 打开本仓库后输入 @concept-learner-skill RAG。

处理：Agent 读取 SKILL.md 的框架（学习目标 → 解释 → 机制 → 案例 → 辨析 → 自测 → 来源），自动产出一份结构化学习网页。

输出：learning-materials/rag.html，套路与本次的 Agent / 上下文 / Skill 资料完全一致。输入一个词，输出一套标准学习资料。

⑥ 概念辨析与使用边界

Skill ≠ Prompt：Prompt 是单次指令；Skill 是带结构、可复用、可版本化的“方法包”。

Skill ≠ Agent：Agent 是执行者；Skill 是 Agent 加载的“知识 / 流程说明书”。

边界：Skill 不能替代模型能力本身；写得太啰嗦或场景不清反而会让 Agent 跑偏。好的 Skill 应“小而专”，讲清何时用、怎么用、产出什么。

⑦ 自测问题

  1. 项目级 Skill 和用户级 Skill 在“存放位置 / 作用范围”上有什么区别？
    提示：前者在仓库 .workbuddy/skills/ 内、仅本仓库生效；后者在用户目录、全局可用。
  2. 为什么 SKILL.md 顶部的 name / description 很重要？
    提示：它们决定 Skill 的标识与“何时被匹配 / 如何被调用”。
  3. 一个“什么都想管”的 Skill 会有什么问题？
    提示：范围模糊会让 Agent 误触发或执行失焦，反而不如小而专的 Skill 好用。
