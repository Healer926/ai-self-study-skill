Agent / 上下文（Context） / Skill 三者关系

① 一句话角色比喻

Skill = 工作手册
规定好“这类任务怎么做”，把经验固化成可复用方法。
Context = 短期记忆 / 工作台
保存当前这次任务的全过程信息，保证 Agent 不丢前文。
Agent = 执行员工
拿着手册、依托记忆，一步步把任务做完。

④ 重点：上下文如何影响 Agent 的工作

Agent 的每一步决策都依赖“当前上下文”里的信息：系统设定、历史步骤、工具返回、用户新要求。上下文就是 Agent 的工作台。

如果上下文长度不足或被不当截断，Agent 会丢失前面的指令和中间结果——即使 Skill 写得再好，也会因为“看不见需求”而跑偏、重复或中断。因此 Agent 设计里常做上下文管理：压缩历史、用检索把相关片段拉回窗口、把长期信息存外部库。

结论：Skill 决定“怎么干”，Context 决定“ Agent 此刻还能记得什么”；两者共同决定 Agent 能不能把事干成。

Agent 工作环节上下文（Context）在其中的作用上下文不足 / 被截断的后果
接收需求系统设定 + 用户目标写入上下文，Agent 才知道“要做什么、按什么规则做”目标不清，Agent 各行其是、反复追问或跑偏
规划步骤历史子目标、已做动作保存在上下文，便于接续推进忘记前面的计划，重复执行或走回头路
工具调用工具返回结果写回上下文，作为下一步决策依据拿不到上一步结果，链路断裂、任务无法收敛
自我纠错错误与反馈留在上下文，Agent 可据此修正同一个错反复犯，无法纠正
交付一致全文上下文保证前后口径、术语、结论一致前后矛盾、结论偏离最初需求

一句话：上下文是 Agent 的“工作台”，台面够大、东西摆得对，Agent 才看得全、干得成；台面太小或中途被清，再好的手册也白搭。

⑤ 重点：Skill 如何沉淀可复用任务知识

没有 Skill 时，每学会一件事都只停留在一次聊天里，下次要重新教。Skill 把“这次怎么把 Agent / 上下文这类概念讲清楚”的框架与步骤写成 SKILL.md，于是：

  • 结构化：明确适用场景、输入、生成步骤、输出结构、来源与自检要求；
  • 可复用：下次只要换一个概念名（如 RAG），同一套框架就产出一份新资料；
  • 可迭代 / 可共享：随仓库提交、做版本管理，团队成员也能直接用。

结论：Skill 是“把一次性对话经验”升级为“项目级可复用能力”的载体，而 Agent + 上下文则是这套能力真正跑起来的执行环境。

沉淀机制说明（Skill 做了什么）带来的可复用价值
结构化把“怎么做”写成固定框架：适用场景、输入、生成步骤、输出结构、来源与自检要求任意新概念都能套同一流程，无需每次重新教
版本化SKILL.md 随仓库提交进 Git，留有修改历史可回滚、可对比、可追溯，质量变化看得见
共享放进 .workbuddy/skills/（项目级）或 ~/.workbuddy/（用户级）即可被 Agent 加载自己或团队成员跨项目直接复用，无需复制粘贴聊天记录
可迭代发现不足就改 SKILL.md，再重新生成资料资料质量随使用持续提升，经验越用越厚

一句话：Skill 把“这次怎么把事讲清楚 / 干漂亮”的隐性经验，固化成一份可被加载、被版本管理、被多人复用的显性文件——这就是任务知识的沉淀。

⑥ 个人理解小结

三者是“能力（Skill）→ 状态（Context）→ 执行（Agent）”的闭环：Skill 提供方法，Context 提供当下可用的信息，Agent 把两者结合起来自主推进任务。理解它们的关系后，我不再把“让 AI 帮我做事”当成一句提示词，而是当成“定义好手册、管理好上下文、交给 Agent 执行”的工程问题——本仓库的 Skill 与三份资料，就是这套认知的落地。

工作手册		 把“这类任务怎么做”固化成的可复用方法包 ①含 YAML（name/description）+ 场景/输入/步骤/输出/自检；②项目级存仓库 .workbuddy/skills/、用户级存 ~/.workbuddy/；③接收任意概念，可迭代共享 易与 Prompt 混淆：Prompt 是一次性指令，Skill 可复用可版本化；易与 Agent 混淆：Skill 是“说明书”，Agent 是“执行者” 被 Agent 加载；其质量决定 Agent“怎么干”
Context
工作台/记忆		 模型本次推理可见的全部文本（token 计），受窗口约束 ①= 系统设定+历史+检索+当前提问；②超窗口即截断，需检索/摘要补全；③默认不跨会话，“记忆”多为应用层模拟 易与“长期记忆”混淆：默认不跨会话；易与“训练数据/参数”混淆：上下文是推理时临时喂入，非参数里的知识；窗口大≠效果好 被 Agent 读写；其充足与否决定 Agent“此刻还能记得什么”
Agent
执行员工		 “感知-思考-行动-观察”闭环的自主执行系统 ①组成=规划+模型+工具+记忆；②靠工具弥补模型“拿不到实时信息/不能执行动作”；③适合目标清、路径不定、需多工具的多步任务 易与脚本/Workflow 混淆：脚本步骤写死、Agent 由模型动态决策；易与 RAG 混淆：RAG 是补上下文的技术，常被 Agent 当工具调用；并非越复杂越好 加载 Skill、读写 Context；是能力真正跑起来的执行环境

一句话串记（高频考点）：Skill 提供“方法”、Context 提供“当下可用的信息”、Agent 把两者结合自主推进任务。三者共同决定一个 AI 系统能不能把事干成——缺 Skill 则每次重教，缺 Context 则 Agent 健忘跑偏，缺 Agent 则方法停在纸面、无法自动执行。
